# 常见问题

### 为什么不用控件选择器，非要截图算坐标？

因为学习通 PC 客户端是 Electron 应用，它的 UIA/无障碍树是空的：`computer_observe` 只能看到
一个 Window 加几个 `Chrome Legacy Window` 面板，`marks` 是空的。既然没有控件可以定位，
就只能「看图 → 算物理坐标 → 用坐标驱动」。

### 为什么点击要用 `drag` 的同点按下抬起？

`computer_act` 的 `click` 动作只接受选择器（`mark`/`aid`/`name`/`index`…），会**忽略** `x`/`y`；
而 `drag` 接受 `fromPoint`/`toPoint`。当 `fromPoint == toPoint` 时，Chromium 收到的是
down → up，会照常派发一次 click。所以「按物理坐标点击」在这套插件里就是用同点 drag 实现的。

### 一次能不能点很多下？

能，但要按批：`computer_act` 默认最多 25 个动作，超过会被整批拒绝（`too-many-actions`），
而且**整批不会执行任何一步**。`xxtong_plan` 已经按这个上限帮你切好了。

### 为什么 `Ctrl+V` 粘不进简答题的答题框？

富文本编辑器禁用了粘贴。可行的办法是 `type_text` 配合 `mode: "sendinput"`，逐字符注入
（中文也能输入）。换行不能用 `\n`，要在两行之间单独发一个 `key: "enter"`。

### 保存之后我写的注释怎么少了几行？

平台对以 `#` 开头的行处理不稳定（实测出现过保存后注释行消失、代码行还在的情况）。
对策：**保存后回读一次**；把关键解释写成不以 `#` 开头的形式，或者干脆多写一行代码注释
并复核。`xxtong_plan` 会在每道简答题后插入一次截图，就是为了让你能及时发现。

### 会不会自动提交？

不会。插件的配置项 `allowSubmitStep` 默认 `false`，`xxtong_plan` 在这种情况下**不生成**提交步骤，
只会生成「暂存」。就算打开了这个开关，调用方也得显式传 `steps: ["draft","submit"]`，
而且提交前必须拿到用户的明确同意。

### 会不会把我的屏幕、答案、日志传到什么地方？

不会。整条链路都是本地操作：`computer-use-windows` 只截目标窗口、把图写到本机并返回路径；
本插件只读写本机文件（标定档与 `preset-plus.json`），不发起任何网络请求。
仓库里也没有任何账号、cookie、日志、机器路径或密钥。

### 支持 macOS / Linux 吗？

不支持。这套实现依赖 Windows 的 UIA 与 `SendInput`（由 `computer-use-windows` 提供），
以及 Windows 版学习通客户端。

### 支持手机端学习通吗？

不支持。手机端要靠 adb / 模拟器，是另一套东西。

### 换了一台显示器就全点偏了？

见 [`CALIBRATION.md`](./CALIBRATION.md)：先把标定档按新分辨率 `derive` 出来，再用
`xxtong_layout_check` 自检，最后拿一道题实测。系统 DPI 缩放、多显示器、窗口有没有最大化
都会影响坐标。

### 答题卡上 19-23 找不到？

那是单选题第二排。窗口不够高时页面根本不渲染它。先把窗口最大化，或者改用滚轮滚到那一题。

### 这套东西会不会违反学校规定？

这由你自己判断和承担。工具只负责把**你自己给出的答案**填进去、把重复的点击自动化，
它不做题也不替你判断；交卷永远由你手动完成。请遵守你所在学校对作业与考试的规定。
